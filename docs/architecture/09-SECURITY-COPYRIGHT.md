## 1. Секрети

| Правило | Реалізація |
|---------|------------|
| Жодного ключа в коді | `.env.example` містить **порожні** змінні; значення — тільки в gitignored `.env` / env секретного менеджера |
| Жодного ключа у відповідях API | Pydantic-схеми не мають полів для ключів; логер застосовує redaction |
| Жодного ключа в артефактах | Quality Agent перевіряє метадані та SRT/JSON на regex_secret |
| CI-сканування | `gitleaks`/`detect-secrets` у pre-commit і CI; падіння збірки на знахідку |
| Історія | Існуючий витік `ELEVENLABS_API_KEY` у публічній історії **не переписується** за рішенням власника; ключ має бути відкликаний у провайдера |
| Platform keys | `FAL_KEY` вилучено; `PEXELS_API_KEY` не використовується; `GOOGLE_API_KEY`, `REPLICATE_API_TOKEN`, `PIXABAY_API_KEY` — опційні та не перевірені тут (Cloudflare 1010) |

**Заборонено** друкувати значення ключів у будь-якому лозі, тесті чи звіті.

## 2. Автентифікація

- **Mistral browser auth** — лише для локальної розробки/dev-профілю; не є
  виробничим механізмом і не замінює keyless-режим.
- Виробничий профіль: локальний користувач + optional SSO; сесії в cookie
  з `HttpOnly`/`Secure`/`SameSite`, CSRF-токен для мутацій.
- Дії з витратами (paid cloud/GPU) вимагають явного `budget_policy=opt_in_cloud`
  і підтвердження користувачем; за замовчуванням `keyless`.

## 3. Мережа

- Поважаємо стандартні `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY`;
  `--network-check` показує лише схему/хост/порт без облікових даних.
- **Не інтегруємо** VPN/анти-DPI/ротацію проксі/Telegram-транзит/tunnel-каталоги
  зі списків користувача: вони каталогуються як `out-of-scope` і не активуються.
- Причини: обхід мережевих обмежень, ризик витоку ключів через недовірені
  релеї, несумісність із YouTube ToS.
- Завантаження — тільки з авторизованих/ліцензованих джерел; перевірка
  `Content-Type`, розміру, sha256; жодного автоматичного fetch конфігів.

## 4. Ліцензії та походження медіа

| Джерело | Статус | Вимога |
|---------|--------|--------|
| Wikimedia / NASA / Archive.org / Openverse | keyless, дозволені | зберегти `source_url`, `author`, `license`, `license_url` у `media_assets` |
| Користувацький файл | дозволено | користувач підтверджує право; зберегти sha256 |
| Авторизоване відео (Clip Studio) | дозволено | `rights_confirmed=1` + `attribution` у фінальному звіті |
| Pexels/Pixabay/FAL/Replicate | опційні | тільки з ключем користувача й явним opt-in |
| Сторінки з невизначеною ліцензією | заборонені | відхилити в Media Agent |

**Provenance report** генерується разом із роликом як `provenance.json`
із переліком усіх шматків медіа, джерелами, ліцензіями, датами й хешами.

## 5. YouTube / copyright

- Заборонено змінювати метадані з метою приховати авторство або обійти Content ID.
- Clip Agent створює **нову редактуру** (монтаж, коментар, субтитри, графіка),
  а не перепаковує вихідний файл.
- Вихідне джерело не завантажується без підтвердження прав.
- Атрибуція в описі/звіті обов'язкова; Quality Agent блокує реліз без неї.
- Дотримання ToS платформи: не автоматизуємо масове завантаження чужих роликів.

## 6. Межі виходного коду

| Категорія | Статус | Правило |
|-----------|--------|---------|
| `reference-only` бенчмарки/конкуренти | MoneyPrinterTurbo, ViMax, agnes-video, OpenMontage (AGPL), Chatterbox (retired) | читати README/ідеї; код не імпортувати |
| GPL + заборона комерції | MoneyPrinterPlus | **тільки README**, жодного копіювання |
| Пропрієтарні | Palmier Pro | лише спостереження за фічами |
| MIT/Apache з не підтвердженим owner | rename/архітектурні ідеї | `needs-verification`, не клонувати автоматично |
| Methodology (ECC, shuohao, motionmaxxing, hypit/SVML, OpenFilm) | ідеї/гейти | позичати принцип, не код; перевірити ліцензію перед reuse |

## 7. Захист від prompt injection і даних

- Текст із вебу/медіа/коментарів обробляється як **дані**, не інструкції.
- Скіл має allowlist інструментів; довільний `exec` із SKILL.md заборонений.
- LLMOutputs валідуються Pydantic-схемами; невалідні → `failed`, не «тихий» fallback.
- За замовчуванням немає телеметрії; логи локальні й не містять секретів/ПД.

## 8. Supply chain

- Піни версій у `requirements*.txt`/`package-lock.json`; optional-пакети —
  окремий файл, ледачий імпорт.
- Хеші/підписи для завантажених моделей (Piper/Whisper/U-2-Net) — у
  `artifacts.sha256`; джерело моделі фіксується.
- CI: `pip-audit`/`npm audit`, `make lint`, `make test`; fails → no merge.

## 9. Інциденти

1. Виявлення секрету → негайне відкликання в провайдера → заміна в `.env`.
2. Історію не переписуємо без окремого рішення власника (поточне рішення — не переписувати).
3. Після інциденту — `gitleaks` по всій історії + оновлення правил redaction.
4. Несанкціоноване джерело медіа → видалити з бібліотеки, інвалідувати
   пов'язані artifacts/etaпи, перезапустити Media Agent.
